# 安装与启用

## 1. 装扩展

OpenChamber → 设置 → 扩展 → 添加扩展，选本仓库根目录（或 Release 里的 zip）。

批准权限：

- `service`：本机回环服务（接 `openchamber_web` 的浏览器动作）
- `opencodePlugin`：`browser_bridge_authorize` / `browser_bridge_status` 工具
- `skills`：给 agent 的授权流程说明

## 2. 设为浏览器提供者

设置 → 通用 → OpenChamber 工具 → **浏览器提供者** → 选「OpenChamber-Browser-bridge」。

这一步决定 `openchamber_web` 的动作发给本扩展而不是内置浏览器面板。

## 3. 首次使用

对话里让 agent 做浏览器操作：

1. agent 先问「是否允许本次对话拉起并操作浏览器」；
2. 你同意后 agent 调 `browser_bridge_authorize` 写授权（12 小时 / 每会话）；
3. 浏览器窗口自动出现，agent 开始操作。

## 4. 浏览器路径

默认按顺序找：`C:\UserProgram\ungoogled-chromium\chrome.exe` → Chrome → Edge →
Vivaldi（%LOCALAPPDATA%）。也可在扩展面板里填任意 Chromium 内核浏览器的 exe 路径。
找不到时 `browser.open` 会返回安装引导，agent 会转述给你。

## 5. 排障

- 面板「桥状态」显示「未连接」→ 还没拉起过浏览器，正常。
- 面板「浏览器 未找到」→ 路径不对，改路径后保存。
- 动作报「本会话尚未授权」→ 让 agent 重新问一次并调用 `browser_bridge_authorize`。
- 改了 service 代码后行为没变 → 宿主不会热重启常驻服务；结束
  `guest-services/<pid>.json` 里 browser-bridge 的进程，宿主会按新 `bundle.js` 重拉。
- 报「浏览器调试端口 N 没有就绪」→ 浏览器可能被重启过、端口变了；服务会先试 profile
  里 `DevToolsActivePort` 的端口，仍失败就重新拉起。
- 服务日志：`<OpenChamber 配置目录>/guest-data/browser-bridge/service.log`。
