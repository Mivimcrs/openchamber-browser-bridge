# 设计说明

## 为什么是「拉起式」

旧方案（dsh-browser 移植）驱动用户**日常浏览器**里装的 Chrome MV3 扩展。它能带真实
登录态，但有两个绕不开的代价：

1. 必须先手动在浏览器里「加载已解压」并在浏览器里常连，装扩展 ≠ 能用；
2. 操控发生在用户正在用的窗口里，容易和人的操作打架，且窗口一关就断。

本扩展反过来：**自己拉起一个独立 Chromium**。代价是登录态要重新登一次（持久 profile
保留），换来的是：

- 装上 OpenChamber 扩展就能用，不需要任何浏览器侧安装；
- 自动化窗口与日常浏览分离，互不干扰；
- 服务重启后能按 profile 复连同一个窗口，动作可跨服务生命周期。

## 架构

```
OpenChamber 宿主
  openchamber_web 工具
        │ POST /browser-control（Bearer service token）
        ▼
  service/bundle.js（宿主拉起的本机回环服务）
        ├─ 授权门（每会话 12h）
        ├─ BrowserManager：spawn Chromium + CDP WebSocket
        └─ provider：12 个动作 → CDP / 页面脚本
        ▼
  独立 Chromium（持久 user-data-dir，--remote-debugging-port=0）
```

宿主在 `contributes.service.provides` 里看到 `browser`，就会把 `openchamber_web` 的
`browser.*` 动作转发给本服务，agent 看到的仍是同一个工具。

## 关键决策

| 决策 | 原因 |
| --- | --- |
| 服务入口打单文件 `bundle.js` | 宿主用 Electron 的 Node 执行入口，单文件避免相对 import 解析问题 |
| 端口 `--remote-debugging-port=0` | Chromium 136+ 禁止默认 profile 开调试端口；0 让浏览器自选，避开 9333/43290 冲突 |
| 授权文件放扩展包根 `.state/` | service 有 `OPENCHAMBER_SERVICE_DATA_DIR`，OpenCode 插件进程没有；包根是两边唯一都能算出的路径 |
| 授权按 sessionId、12h TTL | 用户选的「每会话一次」，既能避免每次动作都问，也不会长期敞口 |
| 服务停止不杀浏览器 | 窗口是用户的；重启用同一 profile 复连，agent 的标签上下文尽量延续 |
| 截图走 `Page.captureScreenshot` | CDP 截图不要求窗口前台，不抢焦点（`captureVisibleTab` 会） |

## 动作映射

| `browser.*` | 实现 |
| --- | --- |
| open | `Target.createTarget` / 复用空白页 → `Page.navigate` → 等 `readyState` |
| snapshot | 页面脚本收集交互元素（selector/bounds/label/options）+ 正文 |
| click | 按 selector（或 text 找 selector）派发 pointer/mouse 事件序列 |
| type | 按元素类型取 value setter 写值 + input/change；`submit` 补 Enter |
| select | 按 label 或 value 精确匹配后写值 + change |
| scroll | 方向滚动或滚到元素；回报实测 scrollY/maxScrollY |
| back / forward | `history.back()/forward()` + 回读 url/title |
| inspect | `getComputedStyle` 关键属性 + bounds |
| capture | `Page.captureScreenshot`（PNG）→ base64 + 读 IHDR 宽高 |
| resize | `Emulation.setDeviceMetricsOverride`，回读实测 innerWidth/Height |
| close | `Target.closeTarget`，只关受控标签 |

## 安全边界

- 服务只绑 `127.0.0.1`，每个请求验 `Authorization: Bearer $OPENCHAMBER_SERVICE_TOKEN`。
- 授权只对写入它的 sessionId 有效；12 小时后自动失效；面板可随时撤销。
- 浏览器用独立 profile，不读取用户日常浏览器的 Cookie/登录态。
- 动作只在受控标签上执行；不提供任意文件系统访问。
